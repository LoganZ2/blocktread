# 方块战车 BLOCKTREAD（Bevy 0.20 原生版）

用方块拼战机，在小行星带里联机空战。服务器权威、客户端预测，走 QUIC（UDP）。

> **tanks 分支：改成地面战车对战，游戏名改为「方块战车 BLOCKTREAD」。** 已完成：
> - **地形**：每局按种子生成一块 1200 米见方的起伏地形（`shared/src/terrain.rs`），四周是山脊，地上散着石头。物理和画面用的是同一套三角面。
> - **战车物理**（`shared/src/drive.rs`）：
>   - 车体是刚体，每个车轮方块下面一根射线悬挂，带轮胎抓地、发动机、刹车、驻车，翻车后按住 R 翻回来。
>   - 和原来的飞行物理一样是服务器、客户端共用的确定性代码，客户端照常预测自己的车。
> - **操作**：W / S 前进、倒车（反着按就是刹车），A / D 转向，鼠标转镜头（武器跟着准星转），Shift 推进器加速，左键开火，按住 R 翻车复位。
> - **行动**：车轮自带动力，加速度 = 各车轮动力之和 / 车重，极速按动力加权取各车轮的极速，车重时打折扣。
>   - 车轮（标准）、小轮（轻快、抓地差、底盘低）、越野轮（又大又重、劲大、抓地强、跑不快）。
>   - 外形：轮胎带胎肩和轮辋，车轮有横纹胎面和五辐轮毂，小轮三辐，越野轮是交错的大块胎纹、深色轮辋加一圈螺栓。
>   - 悬浮器：贴地悬浮，不靠轮胎，转弯特别快但会侧滑；一直耗能量，能量耗尽就落地。
> - **推进器**：只负责加速，按住 Shift 时喷火往前推，很耗能量，尾喷口正后方必须空着。能量在加速中耗尽后，要停 1 秒，并且松开 Shift 再按才能再加速。
> - **武器**（`shared/src/weapons.rs`）：不管装在哪，都立刻指向准星（水平 360°，俯仰 −25° 到 +60°，没有转动延迟）。
>   - 每门武器预先算好哪些方向不会让炮管或弹道穿过自己的车身。朝准星的路上碰到车身就停在那儿，不会绕道（比如翘起来越过车身，或者从另一边绕过去）；只有短的那边被挡、反方向转得过去时才走远路。
>   - 只有炮口对准准星（10° 以内）、而且不朝向车身时才开火；转不过去的武器不开火，不白耗能量。导弹自己会追踪，不受这条限制。
>   - 外形：转动的是一个小炮头，下面有个底座（贴在固定它的那一面上的底板，加一根伸进炮头的立柱），不会悬空。底座优先装在下面，其次背面、侧面、上面。固定它的方块被打掉时，底座会换到还连着的那一面。
>   - 底座和炮头算同一个方块：武器被打掉或随断开的部分一起掉落时，底座跟着一起没。
> - **准星**：屏幕中心的圆是镜头瞄的点，武器就指向那里。
> - **五辆预设战车**（`shared/src/presets.rs`）：越野车（轻型）、黄蜂（轻型悬浮侦察车）、野牛（中型，六个越野轮，车顶轨道炮）、毒蝎（中型导弹车）、犀牛（重型，八个越野轮，车顶轨道炮加两门霰弹炮）。
> - **出车检查**（替换起飞检查）：
>   - 驾驶室和视野、结构连通；
>   - 至少 3 个着地的车轮或悬浮器，没有方块比它们更低；
>   - 重心前面要有车轮负责转向（有悬浮器就不用）；
>   - 功重比 ≥ 0.20；
>   - 重心在车轮围成的范围里，侧翻角太小会提醒；
>   - 悬浮耗能超过回复、推进器喷口被挡、武器四周被挡转不出去，都会提醒。
>   - 服务器选车时按同样的检查拒收开不了的车。
> - **外部界面换成军事工业风**：
>   - 橄榄黑方角面板、琥珀色强调色，主按钮带警示条纹，悬停只亮一条琥珀色线。
>   - 入口页、大厅、选车和车库的背景是白天的野外场地，车停在地上。
>   - 车库是室外的混凝土试车台，部件分组：核心、行动（车轮、小轮、越野轮、悬浮器）、推进、结构、武器、系统。数字键 1–= 对应：驾驶室、车轮、小轮、越野轮、悬浮器、推进器、车体、装甲、机炮、激光炮、轨道炮、导弹舱。
> - **存档**：战车存在 `~/.blocktread/vehicles.json`。第一次启动时从旧目录 `~/.voxwing` 复制设置、战车和 `servers.json` 过来，旧目录不动（飞行版还在用）。分享码改为 `BT1.` 开头；飞行版的 `VW1.` 码会提示「飞机开不了」。
> - **自由混战改成常驻房间**（协议版本 7，客户端和服务器要一起更新）：
>   - 每台服务器只有一个混战房间，不限人数，没有 AI。大厅里选「自由混战」点「进入混战」，开着当前这辆车直接进场（不经过选车，车要先通过出车检查；不分造价档）。随时可以退出，房间里最后一个人走了房间就关掉。
>   - 场上有 2 名以上玩家（观众不算）才开始计时，一局时长是服务器的 `--match-secs`（默认 480 秒）；不到 2 人时显示「等待中」，进行中的一局如果只剩 1 人就作废，再来人重新开始。
>   - 每局按击毁数排名，击毁相同时阵亡少的在前；时间到了宣布获胜者（击毁和阵亡都相同就是平局），记分板自动弹出「本局结果」，休息 10 秒（这期间的击毁不计分）后比分清零开始下一局。中途进来的人从 0 开始，赶上当前这一局的剩余时间。
>   - 左上角显示「等待其他玩家」/「剩余 m:ss」/「下一局 N 秒后开始」和你的名次。
>   - 观战：混战房间里有人时看混战，没人时看正在打的 2v2，都没有就进空房间等人。2v2 不变（排队、AI 补位、选车、击毁上限）。
>   - **试车场**：大厅模式里选「试车场」，用当前这辆车直接进场（不经过选车，车要先通过出车检查）。只有你自己：没有对手、没有 AI、不限时间、不计击毁上限，每次都是同一张地图（固定种子 `SOLO_SEED`），从同一个出发点出发。服务器在客户端里本机运行（只监听 127.0.0.1，随机端口），不连远程服务器；离开时这场就结束。开发用 `--launch solo` 直接进。
> - **改名**：仓库改名为 `LoganZ2/blocktread`，项目里的名字也跟着改了：目录 `blocktread-rs`，crate 和程序 `blocktread-client` / `blocktread-server` / `blocktread_shared` 等，安装包 `Blocktread-macOS.zip` / `Blocktread-Windows.zip`，环境变量 `BLOCKTREAD_BALANCE` / `BLOCKTREAD_BUILD`。只有连接握手的 ALPN 还是 `voxwing/1`：两边不一样就连不上，旧客户端也就收不到「请更新」的提示。
>   - 服务器上的目录和服务也改为 `~/blocktread-server` 和 `blocktread-server`。还按旧名字装着的服务器不用手动改：改名后的第一次部署会自动搬过去（带上 `args.env`，停掉并禁用 `voxwing-server` 服务，换成新的；新版本起不来就恢复旧服务）。`~/voxwing-server` 留在原处，确认没问题后可以删掉。
>
> 下面其余部分描述的还是飞行版（字体一节已更新）。

## 下载

GitHub Actions（`.github/workflows/client.yml`）在每次推送到 main 和每个 PR 时编译客户端：

- **macOS**：`Blocktread-macOS.zip`，解压得到 `Blocktread.app`，Apple Silicon 和 Intel 通用，macOS 11 以上。
- **Windows**：`Blocktread-Windows.zip`，解压得到 `Blocktread.exe`，64 位，不需要另装 VC++ 运行库。

在仓库的 Actions 页面打开最新一次 client 运行，底部 Artifacts 里下载。推送 `v` 开头的标签（例如 `git tag v0.2.0 && git push origin v0.2.0`）会把两个包发布成 GitHub Release，下载链接可以直接发给别人。

两个包都没有付费签名，第一次打开会被系统拦一下：
- macOS 提示「无法验证开发者」：右键（或按住 Control 点）`Blocktread.app` → 打开 → 打开；或者到「系统设置 → 隐私与安全性」里点「仍要打开」。
- Windows 弹出 SmartScreen：点「更多信息」→「仍要运行」。

CI 用 `dist` 配置编译（release 去掉符号，体积小三分之一左右）。

## 运行

需要 Rust 1.97+（Bevy 0.20 的最低要求）。第一次编译 Bevy 要几分钟。

```bash
cargo run -p blocktread-client --release
```

打开游戏先是入口页：在下拉菜单里选服务器（北美 NA、亚洲 ASIA，每个都实时显示延迟，每 3 秒测一次；绿色 < 90 ms、黄色 < 180 ms、红色更高，连不上显示「超时」；没选过时默认延迟最低的那个），点「开始游戏」进入大厅。大厅底部显示当前服务器和延迟，点「更换」或按 Esc 回到入口页。

大厅：中间是你的飞机，两侧的大箭头滑到上一架 / 下一架。飞机是一个循环：最后一架后面是新建位（框角里的大加号，点一下新建一架空白机体并进入机库），再往后又回到第一架；左下选模式：自由混战（服务器上的常驻房间，点「进入混战」直接进场）/ 2v2 团队战（选造价上限，点「开始匹配」）/ 试车场。内置的服务器列表在 `crates/client/src/settings.rs` 的 `BUILT_IN` 里。玩家可以用 `~/.blocktread/servers.json` 改某个服务器的地址或加新服务器，改完重启游戏生效：

```json
[
  { "key": "na", "addr": "10.0.0.10:4433" },
  { "key": "lab", "name": "测试", "code": "LAB", "addr": "192.168.1.20:4433" }
]
```

`key` 是内置服务器的（`na`、`asia`）就只改给出的字段，其他照旧；新的 `key` 就加一个服务器（`addr` 必填，`name`、`code` 不填就用 key）。文件写错时用内置列表，并在启动日志里说明原因。比如在家里时路由器不能从内网绕回自己的公网 IP，就把北美改成家里服务器的内网地址。（开发时还可以用 `--server` 直接指定地址，`--server local` 在客户端里跑一个不等人的服务器，离线也能玩。）

**一局是怎么开始的**：大厅里开始匹配 → 匹配到之后选战机 → 开战 → 结果 → 回大厅。
- 匹配：就在大厅里进行，左下显示已等多久、队列里几个人、几秒后 AI 补位，再按一次（或 Esc）取消。服务器按「模式 + 造价档」排队。人满一局就开；第一个人等了 `--queue-wait` 秒还凑不齐，就用 AI 补齐空位。2v2 里玩家轮流分到蓝队、红队。
- 选战机：30 秒。左边用 ‹ › 在你的机库里挑一架，右边是所有席位和他们正在选的飞机（AI 一开始就选好了）。点一名对手，中间的展示位会换成他的飞机。超出造价上限或没通过起飞检查的飞机选不了。全员确认、或倒计时结束就开战；没确认的人开最后选的那架。
- 对局：阵亡 4 秒后重生。先达到击毁上限（默认 10）的人或队伍获胜，否则时间到（默认 8 分钟）时击毁最多的获胜。
- 结束后显示胜负和记分板，可以「再来一局」（回到大厅并直接用同样的设置重新排队）或「返回大厅」。
- 选战机或对局中途退出，你的席位交给 AI 接着开。

独立服务器（不需要显卡，适合放在云主机上）：

```bash
cargo run -p blocktread-server --release
```

| 参数 | 说明 |
| --- | --- |
| `--port 4433` | UDP 端口 |
| `--bind 0.0.0.0` | 监听地址；`127.0.0.1` 只允许本机 |
| `--queue-wait 15` | 排队多少秒还凑不齐人就用 AI 补位 |
| `--match-secs 480` | 一局的时长 |
| `--kill-limit 10` | 先达到这么多击毁的一方提前获胜 |

模式和造价上限由玩家在客户端里选，服务器不用配置。

## 部署到 Linux 服务器

正式服务器由 CI 部署（`.github/workflows/deploy.yml`）：推一个 `v` 开头的标签时，CI 编译客户端和服务器、发布 GitHub Release，再把这个版本的服务器**并行部署到 `deploy/servers.json` 里的每一台**；也可以在仓库的 Actions → deploy 里手动填一个已发布的版本来部署（回滚也用它），可选只部署到某一台。服务器程序是静态链接的 Linux 二进制（x86_64 和 ARM 各一份），服务器上不需要装 Rust。

每台服务器各自：上传新版本 → **等到这台没人在线再重启**（最多等 20 分钟，超时就放弃并报错，新版本已经传上去，稍后再跑一次即可）→ 切换到新版本并重启 → 检查新版本有没有起来，没起来自动换回旧版本。一台失败不影响其他台。每台保留最近 5 个版本。

**服务器清单** `deploy/servers.json`：每台一项，`name`、`host`、`user`、`host_key`（`ssh-keyscan -t ed25519 地址` 输出里 `ssh-ed25519 …` 那部分），SSH 不是 22 端口时加 `"port": 端口`。部署时读的是 main 分支上的清单，所以回滚到旧版本也会部署到现在的这些服务器。

**加一台服务器**

1. 防火墙放行 UDP 4433（游戏）和 SSH；在家里或内网的机器，要在路由器上把 UDP 4433 和 SSH 端口转发到它。
2. 把 `DEPLOY_SSH_KEY` 对应的公钥加到这台机器部署用户的 `~/.ssh/authorized_keys`。
3. 以这个用户登录，跑一次 `deploy/setup.sh`（把 `blocktread-rs/deploy/` 传上去再运行；非 root 用户要输一次 sudo 密码）。它装好 systemd 用户服务：开机自启、崩溃自动重启，日志用 `journalctl --user-unit blocktread-server -f` 看。
4. 在 `deploy/servers.json` 里加一项，推到 main。

**GitHub 上只有一个 secret**：Settings → Secrets and variables → Actions 里的 `DEPLOY_SSH_KEY`，所有服务器都接受的那把私钥的完整内容。没设置时部署会跳过并给出警告，发版本身不受影响。想每次部署前手动确认，在 Settings → Environments → production 里加上审批人。

服务器的额外参数（比如 `ARGS=--queue-wait 30 --match-secs 600`）写在服务器上的 `~/blocktread-server/args.env`。服务器每 5 秒把版本和在线人数写进 `~/blocktread-server/status.json`。服务器和客户端的协议版本要一致：升了协议的版本，客户端和服务器要一起发（打同一个标签就是一起发）。

客户端内置的服务器写在 `crates/client/src/settings.rs` 的 `BUILT_IN` 里（key、名称、代号、地址）。加正式服务器时 `deploy/servers.json` 和这里各加一项；玩家自己的改动放在 `~/.blocktread/servers.json`。

**开发机（手动）**：`./deploy.sh 用户名@地址 [服务器参数]` 同步源码、在那台机器上编译，在 tmux 会话 `blocktread` 里重启服务器，日志在 `~/blocktread-server.log`。那台机器需要 `build-essential` 和用户目录里的 Rust。

## 联机

自由混战：连同一台服务器的人都在同一个房间里。2v2：选同一造价档就会排到一起。连不上时检查服务器的防火墙放行了 **UDP** 4433（QUIC 不走 TCP）。

连接 5 秒没有响应会自动放弃，大厅里弹出原因，可以直接重试。

## 操作

**飞行**

| 键 | 作用 |
| --- | --- |
| 鼠标 | 转向；光标离屏幕中心越远，转得越快 |
| W / S | 加大 / 减小油门 |
| A / D | 左右翻滚 |
| Shift | 加速（消耗能量） |
| 左键 / 空格 | 开火 |
| 右键 / F | 发射导弹（准星对准目标一会儿即可锁定） |
| T | 切换目标 |
| C | 切换第三人称 / 座舱视角 |
| Tab（按住） | 记分板 |
| H | 显示 / 隐藏操作说明 |
| Esc | 暂停菜单（联机不会真的暂停） |

**准星和命中提示**：圆形准星标的是现在开火、子弹飞到汇聚距离时会在的位置：沿机头方向，再加上子弹继承的飞机自身速度（侧滑或急转时它会偏离机头正前方）。汇聚距离平时是 320 米；机头对准当前目标（T 切换的那架）的提前量位置附近（7° 以内）时，改成到那一点的距离，子弹正好在目标会到的地方交汇。打中时准星周围亮起 X 形的四道短线，白色是打在船体上，蓝色是打在护盾上，击毁是更大的红色 X；同时被打中的那架飞机的框角闪白，并有一声只有射手听得到的确认音（不随距离变小）。屏幕外的敌机在屏幕边缘用三角箭头指示方向。

**机库**

| 键 | 作用 |
| --- | --- |
| B / X / G | 放置 / 擦除 / 喷漆 |
| 1–9、0、-、= | 选择前 12 种部件（其余在左侧面板里点选） |
| 左键 / 右键 | 放置 / 删除 |
| 左键拖动 / 右键拖动 / 滚轮 | 旋转 / 平移 / 缩放视角 |
| Alt + 点击 | 吸取方块类型和颜色 |
| M | 左右镜像 |
| ⌘/Ctrl + Z，⌘/Ctrl + Shift + Z | 撤销 / 重做 |
| Shift + ← → ↑ ↓，Shift + [ ] | 整机左右、上下、前后平移一格（左侧面板「整机平移」里也有按钮） |

驾驶舱、机翼和引擎是起飞必需的。右侧「起飞检查」会实时说明哪里不合格：结构是否连通、推重比、升力、重心是否落在机翼区域内、驾驶舱视野等。武器和其他部件可以随便摆。

共 20 种部件，分五类：

| 分类 | 部件 |
| --- | --- |
| 核心 | 驾驶舱、机翼、引擎 |
| 结构 | 船体、装甲、骨架（很轻，适合拉长机身）、灯块（按涂装颜色发光） |
| 机动 | 陀螺仪（放哪都一样）、尾翼（加强偏航，不产生升力）、小推进器（推力 10，用来补推力或调正推力中心）、姿态推进器（离重心越远越有力） |
| 武器 | 激光炮、机炮、等离子炮、导弹舱、轨道炮（一发连穿 3 个方块，很耗能）、霰弹炮（一次 7 发弹丸，射程短） |
| 系统 | 反应堆、护盾发生器、电容（能量上限 +90，不回复能量） |

方块摆在哪会影响飞行手感（都在 `shared/src/analysis.rs` 里算）。不强制对称，怎么叠都能起飞，只是飞起来会受影响：
- **转动惯量**：俯仰、偏航、翻滚各算各的转动惯量，转速取决于「转向力 ÷ 转动惯量」。重块离重心越远，绕那个轴转得越慢：装甲堆在翼尖翻滚变慢，机身拉长俯仰和偏航变慢。
- **转向力**：机翼离重心越远越有力，前后方向的距离影响俯仰和偏航，左右方向的距离影响翻滚。陀螺仪放在哪都提供同样的转向力，但它重，靠近重心放最划算。
- **推力偏心**：引擎的推力中心偏离重心超过 1/4 格，全速时机头会被拉偏，加速时更明显。战斗中被打掉一侧引擎，飞机会往坏掉的那一侧偏。
- **升力偏心**：每片机翼的升力一样。升力中心偏离重心超过 1/4 格，飞机会一直侧滚：机翼多的一侧被抬起来，重的一侧往下掉。侧滚最多占翻滚能力的 3/4，压杆总能救回来。战斗中掉了半边机翼也是这样。
- **持续火力**：所有武器都耗能。武器总耗能超过反应堆回复时，满火力几秒后能量就会耗尽，之后只能按回复速度开火。机库会同时显示「火力」（爆发）和「持续」火力。

## 平衡

所有方块数值和平衡参数都在 [`crates/shared/balance.ron`](crates/shared/balance.ron) 里，会编译进程序。客户端和服务器加入时会比对这份数据的哈希，不一致就拒绝加入，避免两边按不同数值模拟。

- **造价和档位**：每个方块有造价，整船造价等于各方块之和，武器越多每门越贵（每多一门，全部武器贵 4%）。匹配时可以选档位：轻型 ≤ 80、中型 ≤ 160、重型 ≤ 350，超出的机体在这一局里选不了，AI 也只开符合上限的机型。预设机型正好分布在三档：蜂鸟 67、游隼 122、毒刺 143、犀牛 321。机库和选战机界面会显示造价和所属档位。
- **击毁条件**：驾驶舱被打掉，或者全船剩余耐久低于 25%（结构崩溃）。驾驶舱耐久随造价增长，大船不会被一发打掉。
- **伤害类型**：

  | 类型 | 武器 | 打护盾 | 打装甲 |
  | --- | --- | --- | --- |
  | 能量 | 激光、等离子 | ×0.5 | 不受影响 |
  | 动能 | 机炮、霰弹 | ×1 | 每发减 3 点（最少保留 30%） |
  | 穿甲 | 轨道炮 | ×1 | 几乎不受影响，还能穿透 |
  | 爆炸 | 导弹 | ×1.5 | 不受影响 |

- **范围伤害**：一次爆炸的总伤害最多是标称伤害的 2 倍，按距离分给波及的方块。船体再密实，也不会被一发打出几百伤害。

**调平衡**用 AI 对战模拟：两边 AI 水平相同，所以胜率只反映机体差异。

```bash
cargo run --release -p blocktread-server --example duel -- --games 150 --weapons --equal-cost
```

`--weapons` 会加入游隼的 6 种武器换装版（4 门同种武器）；`--equal-cost` 用装甲和船体把它们补到同一造价，回答「同样的预算下，哪种武器更强」。设 `BLOCKTREAD_BALANCE=改过的 balance.ron` 可以不重新编译直接试数值。当前数值下，6 种换装版在同造价下的互相胜率都在 41–57% 之间，单个对局最高 65%。


## 界面流程

```
大厅（飞机轮播：两侧 ‹ › 滑动，循环，最后一架和第一架之间是新建；模式 / 造价）
  │ 开始匹配：大厅里显示排队进度，再按一次或 Esc 取消
  ▼ 匹配到
选战机 ──全员确认 / 倒计时结束──▶ 飞行 ──时间到 / 击毁上限──▶ 结果 ──返回大厅──▶ 大厅
  │ Esc 退出（席位交给 AI）          ├─ Esc：暂停（继续 / 设置 / 退出对局）   └──再来一局──▶ 大厅（已在排队）
  │                                 ├─ Tab：记分板（2v2 按队分组）
  │                                 └─ 阵亡：谁击落了你 + 重生规则
大厅 ──编辑机体 H──▶ 机库 ──完成──▶ 大厅；设置 S（浮层）；退出 Esc（有确认）
连接失败 / 断开：回到大厅，弹出原因 + 重试
```

**入口页快捷键**：↑ ↓ 换服务器（下拉菜单开着或关着都行），Enter 开始游戏（菜单开着时是选定），S 设置，Esc 关菜单或退出。

**大厅快捷键**：Enter 开始 / 取消匹配，← → 或 , . 滑到上一架 / 下一架，H 机库，S 设置，V 观战，Esc 取消匹配或回到入口页。

**观战**：大厅里的「观战」按钮（或按 V）不驾驶，附身到场上的飞机上看它打。
- 混战房间里有人就看混战；没有的话看正在打的 2v2；都没有就进空的混战房间，等有人进来。看完一局 2v2 可以「继续观战」下一局。
- 镜头和自己开飞机时一样，跟在被观战的飞机后面，C 切到它的座舱视角。左下的船体剖面、护盾、速度、武器、雷达和左上的战绩，都换成这架飞机的。
- ← / →（或 A / D、左键）换一架，AI 排在前面。被观战的飞机被击落时，镜头先绕残骸转两秒，再切到击落它的那架。
- 观众不占记分板和席位。

**声音**：音效是 Kenney 的 CC0 音效库（科幻 + 界面），引擎声是 Freesound 上的真实喷气引擎试车录音，加速时叠加加力燃烧的点火和轰鸣（都是 CC0），背景音乐是 Synth-thetic 的 "Cosmic Navigation"（CC0），都编进程序里，来源和每个文件的处理见 `crates/client/assets/sounds/SOURCES.md`。大部分音效有好几个版本，每次随机挑一个并轻微变调，连射时不会像同一段录音反复播放。音乐在菜单里正常音量，飞行时压低；设置里可以单独调「背景音乐」，0 就是关掉。自己被打中的撞击声按贴身音量播，不随镜头距离变小。各音效的响度在 `src/audio.rs` 的 `EFFECTS` 表里调。

设置和机体保存在 `~/.voxwing/`。分享码（`VW1.` 开头）和网页版通用，但只限原有的 12 种部件；用了新部件的机体，网页版读不出那些方块。

**画面设置**：
- 显示模式：窗口 / 无边框全屏 / 独占全屏。
- 分辨率：窗口模式下只列出放得下的尺寸；独占全屏用显示器自己报告的分辨率，同一分辨率下自动取最高刷新率；无边框全屏跟随显示器。
- 垂直同步。
- 帧率上限：只提供显示器刷新率的整数分之一，比如 120 Hz 显示器上是 120 / 60 / 40 / 30。关掉垂直同步时，另外还能选高于刷新率的上限。

帧率上限的实现在 `client/src/pacing.rs`。显示器只在固定的刷新节拍上换画面（120 Hz 是每 8.3 ms 一次）。如果限帧器按自己的时钟睡眠，就会和这个节拍错开，导致有的帧在屏幕上停一次刷新，有的停两三次，帧数看着很稳，画面却在抽。所以现在的做法是：
- 等待放在渲染线程上，在取交换链图像之前。macOS 上用 CoreVideo display link 拿到真实的 vblank 时刻，每帧都在「目标那次刷新的前一次刷新」刚过时开始渲染，这样有整整一次刷新的时间来渲染和提交，计时抖动远小于这段余量，每帧都正好落在该落的那次刷新上。其他系统拿不到 vblank 相位，只按显示器刷新率的整数倍定时。
- 开着垂直同步时，等于或高于刷新率的上限直接交给垂直同步，不再额外等待。
- 游戏时间按整帧周期推进，而不是用「这帧渲染完的时刻」（那个时刻是抖动的），所以画面运动和实际上屏的节奏完全一致。

`--frame-stats` 每 5 秒打印一次帧间隔、游戏时间步长，以及每帧在屏幕上停了几次刷新。

改显示模式或分辨率后有 15 秒确认：不点“保留”就自动还原，选到显示器不支持的模式也不会卡住。关掉设置等于保留。窗口太矮时设置项会滚动，“完成”按钮始终可见。

## 联机实现

- **服务器权威**：60 Hz tick，每 2 tick 发一次快照（30 Hz）。快照和输入走 QUIC 不可靠数据报；加入、事件、计分走可靠流。
- **客户端预测**：本机飞船用和服务器同一份 `shared::flight` 代码先行模拟。收到快照后回滚到服务器状态，重放未确认的输入；误差不直接跳变，而是作为视觉偏移逐渐衰减。
- **时间同步**：客户端微调本地 tick 速度，让输入比服务器领先约 3 tick 到达。
- **远端飞船**：延迟 6 tick 做 Hermite 插值。
- **延迟补偿**：服务器保存最近的位置历史，判定命中时按射击者的视图延迟回溯。
- **方块破坏**：只同步「哪个方块被打掉」的事件。脱落判定（`ShipBody::settle`）是确定性的，各端各算各的，碎块物理只在本地模拟。

无头压测（3 个机器人客户端，单向延迟 50 ms）：每 450 次预测校验约 2–4 次和解修正，每个客户端约 8 KB/s，服务器 tick 平均 0.02 ms。

```bash
cargo run -p blocktread_client_core --example bots -- --clients 3 --secs 60 --latency 50 --mode 2v2 --match-secs 20   # 机器人排队、选车、开打、看结果、再排队
cargo run -p blocktread_client_core --example bots -- --clients 4 --secs 75 --match-secs 20   # 机器人进混战房间，打印每局的开始、结束和排名
cargo test -p blocktread_shared
cargo run -p blocktread_shared --example stats   # 各预设机型的数值，以及掉一台引擎后的变化，调平衡用
```
