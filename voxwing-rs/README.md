# 体素星翼 VOXWING（Bevy 0.20 原生版）

用方块拼战机，在小行星带里联机空战。服务器权威、客户端预测，走 QUIC（UDP）。

## 下载

GitHub Actions（`.github/workflows/client.yml`）在每次推送到 main 和每个 PR 时编译客户端：

- **macOS**：`Voxwing-macOS.zip`，解压得到 `Voxwing.app`，Apple Silicon 和 Intel 通用，macOS 11 以上。
- **Windows**：`Voxwing-Windows.zip`，解压得到 `Voxwing.exe`，64 位，不需要另装 VC++ 运行库。

在仓库的 Actions 页面打开最新一次 client 运行，底部 Artifacts 里下载。推送 `v` 开头的标签（例如 `git tag v0.2.0 && git push origin v0.2.0`）会把两个包发布成 GitHub Release，下载链接可以直接发给别人。

两个包都没有付费签名，第一次打开会被系统拦一下：
- macOS 提示「无法验证开发者」：右键（或按住 Control 点）`Voxwing.app` → 打开 → 打开；或者到「系统设置 → 隐私与安全性」里点「仍要打开」。
- Windows 弹出 SmartScreen：点「更多信息」→「仍要运行」。

CI 用 `dist` 配置编译（release 去掉符号，体积小三分之一左右）。

## 运行

需要 Rust 1.97+（Bevy 0.20 的最低要求）。第一次编译 Bevy 要几分钟。

```bash
cargo run -p voxwing-client --release
```

打开游戏就是大厅：中间是你的飞机，两侧的大箭头滑到上一架 / 下一架。飞机是一个循环：最后一架后面是新建位（框角里的大加号，点一下新建一架空白机体并进入机库），再往后又回到第一架；左下选模式（自由混战 6 人 / 2v2 团队战）和造价上限，点「开始匹配」。匹配连的是固定的服务器 `38.76.173.217:4433`（客户端里的 `SERVER` 常量；开发时可以用 `--server` 换，`--server local` 在客户端里跑一个不等人的服务器，离线也能玩）。

**一局是怎么开始的**：大厅里开始匹配 → 匹配到之后选战机 → 开战 → 结果 → 回大厅。
- 匹配：就在大厅里进行，左下显示已等多久、队列里几个人、几秒后 AI 补位，再按一次（或 Esc）取消。服务器按「模式 + 造价档」排队。人满一局就开；第一个人等了 `--queue-wait` 秒还凑不齐，就用 AI 补齐空位。2v2 里玩家轮流分到蓝队、红队。
- 选战机：30 秒。左边用 ‹ › 在你的机库里挑一架，右边是所有席位和他们正在选的飞机（AI 一开始就选好了）。点一名对手，中间的展示位会换成他的飞机。超出造价上限或没通过起飞检查的飞机选不了。全员确认、或倒计时结束就开战；没确认的人开最后选的那架。
- 对局：阵亡 4 秒后重生。先达到击毁上限（默认 10）的人或队伍获胜，否则时间到（默认 8 分钟）时击毁最多的获胜。
- 结束后显示胜负和记分板，可以「再来一局」（回到大厅并直接用同样的设置重新排队）或「返回大厅」。
- 选战机或对局中途退出，你的席位交给 AI 接着开。

独立服务器（不需要显卡，适合放在云主机上）：

```bash
cargo run -p voxwing-server --release
```

| 参数 | 说明 |
| --- | --- |
| `--port 4433` | UDP 端口 |
| `--bind 0.0.0.0` | 监听地址；`127.0.0.1` 只允许本机 |
| `--queue-wait 15` | 排队多少秒还凑不齐人就用 AI 补位 |
| `--match-secs 480` | 一局的时长 |
| `--kill-limit 10` | 先达到这么多击毁的一方提前获胜 |

模式和造价上限由玩家在客户端里选，服务器不用配置。

## 部署到 Linux 服务器

正式服务器由 CI 部署（`.github/workflows/deploy.yml`）：推一个 `v` 开头的标签时，CI 编译客户端和服务器、发布 GitHub Release，再把这个版本的服务器部署上去；也可以在仓库的 Actions → deploy 里手动填一个已发布的版本来部署（回滚也用它）。服务器程序是静态链接的 Linux 二进制（x86_64 和 ARM 各一份），服务器上不需要装 Rust。

每次部署：上传新版本 → **等到没人在线再重启**（最多等 20 分钟，超时就放弃并报错，新版本已经传上去，稍后再跑一次即可）→ 切换到新版本并重启 → 检查新版本有没有起来，没起来自动换回旧版本。服务器保留最近 5 个版本。

**一次性准备**

1. 云服务商的安全组放行 UDP 4433（游戏）和 TCP 22（SSH）。
2. 服务器上建一个普通用户（比如 `voxwing`），SSH 只允许密钥登录。
3. 生成一对只给 CI 用的部署密钥，公钥加到这个用户的 `~/.ssh/authorized_keys`：
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/voxwing-deploy -N "" -C voxwing-deploy
   ```
4. 以这个用户登录服务器，跑一次 `deploy/setup.sh`（把 `voxwing-rs/deploy/` 传上去再运行；要输一次 sudo 密码）。它装好 systemd 用户服务：开机自启、崩溃自动重启，日志用 `journalctl --user -u voxwing-server -f` 看。
5. 仓库 Settings → Secrets and variables → Actions 里加四个 secret：

   | 名字 | 内容 |
   | --- | --- |
   | `DEPLOY_HOST` | 服务器 IP 或域名 |
   | `DEPLOY_USER` | 第 2 步的用户名 |
   | `DEPLOY_SSH_KEY` | 第 3 步私钥文件的全部内容 |
   | `DEPLOY_KNOWN_HOSTS` | `ssh-keyscan -t ed25519 服务器IP` 的输出 |

   没设置这些时，部署会跳过并给出警告，发版本身不受影响。想每次部署前手动确认，在 Settings → Environments → production 里加上审批人。

服务器的额外参数（比如 `ARGS=--queue-wait 30 --match-secs 600`）写在服务器上的 `~/voxwing-server/args.env`。服务器每 5 秒把版本和在线人数写进 `~/voxwing-server/status.json`。服务器和客户端的协议版本要一致：升了协议的版本，客户端和服务器要一起发（打同一个标签就是一起发）。

客户端连的服务器地址写在 `crates/client/src/main.rs` 的 `SERVER` 常量里，换服务器就改这一行。

**开发机（手动）**：`./deploy.sh 用户名@地址 [服务器参数]` 同步源码、在那台机器上编译，在 tmux 会话 `voxwing` 里重启服务器，日志在 `~/voxwing-server.log`。那台机器需要 `build-essential` 和用户目录里的 Rust。

## 联机

所有人连同一台服务器，选同一模式、同一造价档就会排到一起。连不上时检查服务器的防火墙放行了 **UDP** 4433（QUIC 不走 TCP）。

连接 5 秒没有响应会自动放弃，大厅里弹出原因，可以直接重试。

驾驶舱、机翼和引擎是起飞必需的。右侧「起飞检查」会实时说明哪里不合格：结构是否连通、推重比、升力、重心是否落在机翼区域内、驾驶舱视野等。武器和其他部件可以随便摆。

共 20 种部件，分五类：

| 分类 | 部件 |
| --- | --- |
| 核心 | 驾驶舱、机翼、引擎 |
| 结构 | 船体、装甲、骨架（很轻，适合拉长机身）、灯块（按涂装颜色发光） |
| 机动 | 陀螺仪（放哪都一样）、尾翼（加强偏航，不产生升力）、小推进器（推力 10，用来补推力或调正推力中心）、姿态推进器（离重心越远越有力） |
| 武器 | 激光炮、机炮、等离子炮、导弹舱、轨道炮（一发连穿 3 个方块，很耗能）、霰弹炮（一次 7 发弹丸，射程短） |
| 系统 | 反应堆、护盾发生器、电容（能量上限 +90，不回复能量） |

方块摆在哪会影响飞行手感（都在 `shared/src/analysis.rs` 里算）。不强制对称，怎么叠都能起飞，只是飞起来会受影响：
- **转动惯量**：俯仰、偏航、翻滚各算各的转动惯量，转速取决于「转向力 ÷ 转动惯量」。重块离重心越远，绕那个轴转得越慢：装甲堆在翼尖翻滚变慢，机身拉长俯仰和偏航变慢。
- **转向力**：机翼离重心越远越有力，前后方向的距离影响俯仰和偏航，左右方向的距离影响翻滚。陀螺仪放在哪都提供同样的转向力，但它重，靠近重心放最划算。
- **推力偏心**：引擎的推力中心偏离重心超过 1/4 格，全速时机头会被拉偏，加速时更明显。战斗中被打掉一侧引擎，飞机会往坏掉的那一侧偏。
- **升力偏心**：每片机翼的升力一样。升力中心偏离重心超过 1/4 格，飞机会一直侧滚：机翼多的一侧被抬起来，重的一侧往下掉。侧滚最多占翻滚能力的 3/4，压杆总能救回来。战斗中掉了半边机翼也是这样。
- **持续火力**：所有武器都耗能。武器总耗能超过反应堆回复时，满火力几秒后能量就会耗尽，之后只能按回复速度开火。机库会同时显示「火力」（爆发）和「持续」火力。

## 平衡

所有方块数值和平衡参数都在 [`crates/shared/balance.ron`](crates/shared/balance.ron) 里，会编译进程序。客户端和服务器加入时会比对这份数据的哈希，不一致就拒绝加入，避免两边按不同数值模拟。

- **造价和档位**：每个方块有造价，整船造价等于各方块之和，武器越多每门越贵（每多一门，全部武器贵 4%）。匹配时可以选档位：轻型 ≤ 80、中型 ≤ 160、重型 ≤ 350，超出的机体在这一局里选不了，AI 也只开符合上限的机型。预设机型正好分布在三档：蜂鸟 67、游隼 122、毒刺 143、犀牛 321。机库和选战机界面会显示造价和所属档位。
- **击毁条件**：驾驶舱被打掉，或者全船剩余耐久低于 25%（结构崩溃）。驾驶舱耐久随造价增长，大船不会被一发打掉。
- **伤害类型**：

  | 类型 | 武器 | 打护盾 | 打装甲 |
  | --- | --- | --- | --- |
  | 能量 | 激光、等离子 | ×0.5 | 不受影响 |
  | 动能 | 机炮、霰弹 | ×1 | 每发减 3 点（最少保留 30%） |
  | 穿甲 | 轨道炮 | ×1 | 几乎不受影响，还能穿透 |
  | 爆炸 | 导弹 | ×1.5 | 不受影响 |

- **范围伤害**：一次爆炸的总伤害最多是标称伤害的 2 倍，按距离分给波及的方块。船体再密实，也不会被一发打出几百伤害。

**调平衡**用 AI 对战模拟：两边 AI 水平相同，所以胜率只反映机体差异。

```bash
cargo run --release -p voxwing-server --example duel -- --games 150 --weapons --equal-cost
```

`--weapons` 会加入游隼的 6 种武器换装版（4 门同种武器）；`--equal-cost` 用装甲和船体把它们补到同一造价，回答「同样的预算下，哪种武器更强」。设 `VOXWING_BALANCE=改过的 balance.ron` 可以不重新编译直接试数值。当前数值下，6 种换装版在同造价下的互相胜率都在 41–57% 之间，单个对局最高 65%。


## 界面流程

```
大厅（飞机轮播：两侧 ‹ › 滑动，循环，最后一架和第一架之间是新建；模式 / 造价）
  │ 开始匹配：大厅里显示排队进度，再按一次或 Esc 取消
  ▼ 匹配到
选战机 ──全员确认 / 倒计时结束──▶ 飞行 ──时间到 / 击毁上限──▶ 结果 ──返回大厅──▶ 大厅
  │ Esc 退出（席位交给 AI）          ├─ Esc：暂停（继续 / 设置 / 退出对局）   └──再来一局──▶ 大厅（已在排队）
  │                                 ├─ Tab：记分板（2v2 按队分组）
  │                                 └─ 阵亡：谁击落了你 + 重生规则
大厅 ──编辑机体 H──▶ 机库 ──完成──▶ 大厅；设置 S（浮层）；退出 Esc（有确认）
连接失败 / 断开：回到大厅，弹出原因 + 重试
```

**大厅快捷键**：Enter 开始 / 取消匹配，← → 或 , . 滑到上一架 / 下一架，H 机库，S 设置，V 观战，Esc 取消匹配或退出。

**观战**：大厅里的「观战」按钮（或按 V）不驾驶，附身到场上的飞机上看它打。
- 服务器上有对局在打就看那一局；没有的话开一局全 AI 的自由混战。看完一局可以「继续观战」下一局。
- 镜头和自己开飞机时一样，跟在被观战的飞机后面，C 切到它的座舱视角。左下的船体剖面、护盾、速度、武器、雷达和左上的战绩，都换成这架飞机的。
- ← / →（或 A / D、左键）换一架，AI 排在前面。被观战的飞机被击落时，镜头先绕残骸转两秒，再切到击落它的那架。
- 观众不占记分板和席位。

**声音**：音效是 Kenney 的 CC0 音效库（科幻 + 界面），引擎声是 Freesound 上的真实喷气引擎试车录音，加速时叠加加力燃烧的点火和轰鸣（都是 CC0），背景音乐是 Synth-thetic 的 "Cosmic Navigation"（CC0），都编进程序里，来源和每个文件的处理见 `crates/client/assets/sounds/SOURCES.md`。大部分音效有好几个版本，每次随机挑一个并轻微变调，连射时不会像同一段录音反复播放。音乐在菜单里正常音量，飞行时压低；设置里可以单独调「背景音乐」，0 就是关掉。各音效的响度在 `src/audio.rs` 的 `EFFECTS` 表里调。

设置和机体保存在 `~/.voxwing/`。分享码（`VW1.` 开头）和网页版通用，但只限原有的 12 种部件；用了新部件的机体，网页版读不出那些方块。

**画面设置**：
- 显示模式：窗口 / 无边框全屏 / 独占全屏。
- 分辨率：窗口模式下只列出放得下的尺寸；独占全屏用显示器自己报告的分辨率，同一分辨率下自动取最高刷新率；无边框全屏跟随显示器。
- 垂直同步。
- 帧率上限：只提供显示器刷新率的整数分之一，比如 120 Hz 显示器上是 120 / 60 / 40 / 30。关掉垂直同步时，另外还能选高于刷新率的上限。

帧率上限的实现在 `client/src/pacing.rs`。显示器只在固定的刷新节拍上换画面（120 Hz 是每 8.3 ms 一次）。如果限帧器按自己的时钟睡眠，就会和这个节拍错开，导致有的帧在屏幕上停一次刷新，有的停两三次，帧数看着很稳，画面却在抽。所以现在的做法是：
- 等待放在渲染线程上，在取交换链图像之前。macOS 上用 CoreVideo display link 拿到真实的 vblank 时刻，每帧都在「目标那次刷新的前一次刷新」刚过时开始渲染，这样有整整一次刷新的时间来渲染和提交，计时抖动远小于这段余量，每帧都正好落在该落的那次刷新上。其他系统拿不到 vblank 相位，只按显示器刷新率的整数倍定时。
- 开着垂直同步时，等于或高于刷新率的上限直接交给垂直同步，不再额外等待。
- 游戏时间按整帧周期推进，而不是用「这帧渲染完的时刻」（那个时刻是抖动的），所以画面运动和实际上屏的节奏完全一致。

`--frame-stats` 每 5 秒打印一次帧间隔、游戏时间步长，以及每帧在屏幕上停了几次刷新。

改显示模式或分辨率后有 15 秒确认：不点“保留”就自动还原，选到显示器不支持的模式也不会卡住。关掉设置等于保留。窗口太矮时设置项会滚动，“完成”按钮始终可见。

## 代码结构

```
crates/
  shared/       确定性模拟，不依赖 Bevy：方块与机体分析、飞行物理、武器、AI、协议
  net/          QUIC 端点（quinn + 自签证书）和带长度前缀的帧
  server/       权威服务器：匹配大厅（hub.rs：排队、AI 补位、选战机、结算）、每局一个 60 Hz 模拟（game.rs）、延迟补偿；也可作为库嵌入客户端
  client-core/  联机客户端核心，不依赖 Bevy：预测、和解、插值、时间同步
  client/       Bevy 客户端
    ui/         自己的组件库（见下）
    screens/    大厅（menu.rs：模式、匹配；carousel.rs：飞机轮播）、选战机 / 结果（matching.rs）、设置浮层
    hangar.rs   机库
    flight/     飞行：HUD、特效、环境、飞船同步
```

### UI 组件库（`crates/client/src/ui`）

视觉语言是克制的舰桥显示屏：深色纯色面板、切角、1px 细线，不用渐变和发光；青色只用于小面积强调和主按钮，橙色只用于警报。布局有一套固定尺度（`ui/mod.rs`）：所有间距都是 4 的倍数，屏幕边距 24，面板内边距 20，区块之间 16、区块内 8，控件高度 36（主按钮 52）。所有面板、按钮、标签和分段式属性条都由一个 UI 着色器（`ui/plate.wesl`）绘制。

自带字体（都是 SIL Open Font License，许可证在 `crates/client/assets/fonts/`，编译时嵌入程序）：

| 字体 | 用途 |
| --- | --- |
| 得意黑 Smiley Sans | 只用于游戏标题和战斗播报（原版文件，未修改） |
| Chakra Petch | 数字、英文标签、HUD 读数。垂直度量（hhea/OS2 的 ascender/descender）改成和 Noto Sans SC 相同，两种字体并排时基线才对得齐 |
| Noto Sans SC | 正文和各级标题（可变字重：正文 500，标签 700，标题 800）；按游戏用字和 3755 个常用汉字做了子集。子集外的字（比如玩家起的名字）回退到系统中文字体 |

## 联机实现

- **服务器权威**：60 Hz tick，每 2 tick 发一次快照（30 Hz）。快照和输入走 QUIC 不可靠数据报；加入、事件、计分走可靠流。
- **客户端预测**：本机飞船用和服务器同一份 `shared::flight` 代码先行模拟。收到快照后回滚到服务器状态，重放未确认的输入；误差不直接跳变，而是作为视觉偏移逐渐衰减。
- **时间同步**：客户端微调本地 tick 速度，让输入比服务器领先约 3 tick 到达。
- **远端飞船**：延迟 6 tick 做 Hermite 插值。
- **延迟补偿**：服务器保存最近的位置历史，判定命中时按射击者的视图延迟回溯。
- **方块破坏**：只同步「哪个方块被打掉」的事件。脱落判定（`ShipBody::settle`）是确定性的，各端各算各的，碎块物理只在本地模拟。

无头压测（3 个机器人客户端，单向延迟 50 ms）：每 450 次预测校验约 2–4 次和解修正，每个客户端约 8 KB/s，服务器 tick 平均 0.02 ms。

```bash
cargo run -p voxwing_client_core --example bots -- --clients 3 --secs 60 --latency 50 --mode 2v2 --match-secs 20   # 机器人排队、选机、开打、看结果、再排队
cargo test -p voxwing_shared
cargo run -p voxwing_shared --example stats   # 各预设机型的数值，以及掉一台引擎后的变化，调平衡用
```

## 开发用参数（客户端）

| 参数 | 说明 |
| --- | --- |
| `--server 地址:端口\|local` | 不连 `38.76.173.217:4433`，改连这个地址；`local` 在客户端里跑一个服务器（不排队，AI 马上补齐） |
| `--launch ffa\|2v2\|watch` | 启动后直接开始匹配或观战 |
| `--local` | `--server local` 只监听 127.0.0.1（不会触发防火墙弹窗） |
| `--autopilot` | AI 代飞；选战机时也会自己确认 |
| `--latency 毫秒` | 模拟单向延迟 |
| `--screen error\|hangar\|settings` | 从指定界面启动（error：大厅里弹出连接失败） |
| `--screenshot 路径 --after 秒 [--count N --every 秒] [--exit]` | 定时截图 |
| `--offscreen` | 渲染到离屏图像（大小取设置里的窗口尺寸）并隐藏窗口：屏幕锁定时也能截图，也不会弹窗打扰。同时静音（等于 `--mute`） |
| `--mute` | 完全不出声，连音频设备都不打开 |
| `--force pause\|board\|side\|tip\|revert\|next\|hover:秒` | 到时间后强制显示暂停菜单、记分板、悬停提示、显示设置的还原倒计时，切到飞船侧面的镜头（看尾气），（next）每 2 秒让大厅轮播向右滑一格，或（hover）把大厅的箭头和加号显示成悬停状态。可以写多个 `--force` |
| `--frame-stats` | 每 5 秒打印帧节奏统计（见上面「帧率上限」） |
| `--port 端口` | `--server local` 的 UDP 端口（默认 4433，被占用时自动换一个空闲端口） |
